## エラーの3つの種類

プログラムのエラーは、見つかるタイミングによって3つに分けられます。

コンパイルエラーは、実行の前に見つかるエラーです。
型の不一致や、文法の間違いなどが該当します。
実行前に見つかるので、3つの中で直すのがもっとも簡単です。

実行時エラーは、実行中に発生するエラーです。
次のコードは文法としては正しいので実行できますが、範囲外のインデックスにアクセスした時点で `RangeError` が発生して停止します。

```dart
void main() {
  List<int> numbers = [1, 2, 3];
  print(numbers[5]);
}
```

論理エラーは、プログラムは最後まで動くのに結果が間違っているものです。
原因は考え方や書き方のミスで、エラーメッセージが出ないので、もっとも見つけにくいエラーです。

```dart
void main() {
  int a = 10;
  int b = 20;

  // 平均を求めるつもりが、括弧を忘れてb / 2を先に計算している
  double average = a + b / 2;
  print(average);
}
```

```text
20
```

## nullの扱い

型に `?` を付けた変数は `null` を持てます。
Dartのコンパイラは `null` かもしれない変数の使い方を調べ、確認せずに使おうとするとコンパイルエラーにします。

```dart
void main() {
  String? name;

  // print(name.length); // コンパイルエラー: nameはnullかもしれない

  if (name == null) {
    print('名前が設定されていません');
  } else {
    print(name.length);
  }
}
```

`null` の値を誤って使うエラーは多くの言語で頻発する問題ですが、Dartではこの仕組みにより実行前に防ぎやすくなっています。

## try-catch

ネットワークの切断やユーザーの入力ミスのように、プログラムの外の要因で起きるエラーは完全にはなくせません。
実行中に発生するこうしたエラーを例外と呼びます。
`try-catch` を使うと、例外が起きても強制終了せずに処理を続けられます。

```dart
void main() {
  String userInput = 'abc';

  try {
    int number = int.parse(userInput);
    print('入力された数値: $number'); // ここは実行されません
  } catch (e) {
    print('数値に変換できませんでした: $e');
  }

  print('プログラムを続行します');
}
```

`try` の中で例外が起きると、残りの処理を飛ばして `catch` に移ります。
変数 `e` には、例外の内容が入ります。
`catch` の処理が終わると、その後ろの処理に進みます。

数字以外の文字を渡すと、`int.parse` は `FormatException` という例外を発生させます。
実際のアプリでは、これを受け止めて再入力を促します。

## 例外の種類ごとに処理を分ける

`on 例外の型` と書くと、種類ごとに異なる処理を書けます。
上から順に照合され、最初に一致したものが実行されます。

```dart
void main() {
  String userInput = 'abc';

  try {
    print(int.parse(userInput));
  } on FormatException {
    print('数値を入力してください');
  } catch (e) {
    print('その他のエラー: $e');
  }
}
```

## ExceptionとError

実行中に発生するものは、大きく2種類に分かれます。

- `Exception`：入力の誤りや通信の失敗のように、プログラムが正しくても起こりうるものです。`FormatException` が該当します。`try-catch` で受け止めて対処します。
- `Error`：プログラムの誤りを表すものです。範囲外のインデックスで発生する `RangeError` が該当します。受け止めるのではなく、コードを直します。

型を指定しない `catch (e)` は、どちらも受け止めます。
`Error` まで受け止めると、直すべき誤りに気付きにくくなるので、想定している例外は `on` で指定します。

## finally

`finally` の中は、例外が起きても起きなくても必ず実行されます。
開いたファイルを閉じるといった後始末に使います。

`throw` は、例外を自分で発生させる命令です。
次のコードは、ファイルが見つからなかった状況を再現しています。

```dart
void main() {
  try {
    print('ファイルを開きます');
    throw Exception('ファイルが見つかりません');
  } catch (e) {
    print('エラー: $e');
  } finally {
    print('ファイルを閉じます');
  }
}
```

```text
ファイルを開きます
エラー: Exception: ファイルが見つかりません
ファイルを閉じます
```

## デバッグの進め方

エラーの原因を探して直す作業をデバッグと呼びます。
基本の進め方は次のとおりです。

1. エラーメッセージを読む。何が起きたかはほとんどの場合そこに書かれています。
2. 場所を絞り込む。問題が起きる最小限のコードを切り出すと、原因が見えやすくなります。
3. `print` で変数の値を確かめる。期待した値と異なる最初の場所を探します。Flutterでも同じ方法が使えます。

実行時エラーでは、スタックトレースも手がかりになります。
エラーが発生するまでに、どの関数がどの順番で呼び出されたかの記録で、ファイル名と行番号が書かれています。

テストするときは、境界の値と変わった入力を試すと不具合を見つけやすくなります。
0から100の値を受け付ける処理なら、-1、0、100、101を確認します。
文字列を扱う処理なら、空文字列、1文字、スペースを含む文字列、数字、日本語などを試します。

これでDartの文法の学習は一区切りです。
第26章からはFlutterでアプリを作りながら、必要な文法を追加で学びます。

::: tip 第3部のまとめ
- 関数は処理に名前を付けてまとめたもので、1つの仕事に絞ると読みやすくなります。
- 変数はできるだけ狭いスコープで宣言します。
- 名前付き引数は `{ }` で定義し、必須にするときは `required` を付けます。
- クラスは設計図で、フィールドで属性を、メソッドで行動を表します。
- `_` で始まる名前はファイルの外から使えません。
- 想定できる例外は `try-catch` で受け止め、`Error` はコードを直します。
:::
