この章は発展の内容で、講義動画では扱いません。

Webサービスの裏側のコードは開発者のサーバーで動きますが、スマートフォンのアプリは利用者の端末で動きます。
端末に渡したものは、手間をかければ取り出せるものと考える必要があります。
この前提を踏まえて、秘密の情報の扱い方を学びます。

## APIキーをコードに書く問題

Web APIの多くは、利用者を識別するためにAPIキーという文字列を要求します。
課金を伴うAPIでは、キーを知られると他人に使われ、その料金を請求されることがあります。

もっとも単純な書き方は、コードに直接書くことです。

```dart
const apiKey = 'abcd1234'; // このように書かない
```

この書き方には、漏れる経路が2つあります。

1つ目はGitHubです。
コードをGitHubに公開すると、そのキーも公開されます。

2つ目はアプリそのものです。
ストアで配布するアプリのファイルを解析すると、中に含まれる文字列を取り出せます。
難読化で読みにくくすることはできても、アプリが実行時に使う値である以上、取り出せなくすることはできません。
この2つは別の問題で、対策も別々に考えます。

## コードとキーを分離する

GitHubへの流出は、キーをコードと別のファイルに置くことで防げます。
ここでは `--dart-define-from-file` を使います。

プロジェクト直下に `env.json` を作ります。

```json
{
  "API_KEY": "abcd1234"
}
```

第2章で学んだ `.gitignore` に追記して、Gitの管理対象から外します。

```text
env.json
```

値は `String.fromEnvironment` で読み出します。
ビルド時に値が埋め込まれる仕組みなので、`const` を付けます。

```dart
const apiKey = String.fromEnvironment('API_KEY');
```

実行するときに、ファイルを指定します。

```bash
flutter run --dart-define-from-file=env.json
```

`.gitignore` は、すでにコミットしたファイルには効きません。
キーを誤ってコミットした場合、ファイルを消すコミットを追加しても、履歴には残ります。
公開されたキーは漏れたものとして扱い、提供元の管理画面で無効にして、新しいキーを発行します。

この方法で防げるのは、GitHubからの流出だけです。
値はアプリに埋め込まれるので、2つ目の経路は残ります。

## 秘密のキーはサーバーに置く

アプリから取り出せないようにするには、キーをアプリに入れないことです。
自分のサーバーを間に置き、キーはサーバーだけが持ちます。

```text
アプリ → 自分のサーバー（キーを保持） → 外部のWeb API
```

アプリは自分のサーバーのURLを呼び出すだけなので、コードにキーが現れません。

```dart
final response = await Dio().get('https://api.example.com/weather');
```

そのサーバーは誰でも呼び出せてしまうので、サーバー側でログインの確認や、回数の制限を行います。
そうしないと、キーが漏れないとしても、サーバーを通じて他人に使われます。

実際の判断は、キーの種類によって変わります。

- 利用料金が発生するキーや、強い権限を持つキー：サーバーに置きます。生成AIのAPIキーなどが該当します。
- アプリに含めることを想定して発行されるキー：アプリに入れてかまいません。地図サービスのキーのように、提供元の管理画面でアプリのBundle IDなどに利用を制限できるものです。

どちらにあたるかは、そのサービスのドキュメントで確認します。

## shared_preferencesに機密情報を保存してはいけない理由

第48章の `shared_preferences` の保存先は、暗号化されていない普通のファイルです。
iOSではプロパティリスト、AndroidではXMLの形式で保存されます。

シミュレータで確かめられます。
第48章のカウンターアプリを起動したまま、次のコマンドを実行します。
`com.example.myApp` の部分には、自分のアプリのBundle IDを指定します。
Bundle IDについては第54章で説明します。

```bash
cd "$(xcrun simctl get_app_container booted com.example.myApp data)/Library/Preferences"
```

```bash
plutil -p com.example.myApp.plist
```

保存した値がそのまま表示されます。
他の項目が一緒に表示されることや、ファイルへの反映に少し時間がかかることがあります。

```text
{
  "flutter.counter" => 10
}
```

通常、他のアプリはこのファイルを読めません。
OSがアプリごとに保存場所を分けているからです。
ただし、この保護は万全ではありません。
OSの制限を解除した端末や、端末のバックアップを経由すれば、ファイルを読める場合があります。

したがって、保存してよいものとよくないものを分けます。

| 保存してよいもの | 保存してはいけないもの |
| --- | --- |
| 画面のテーマ、並び順、チュートリアルの完了フラグ | パスワード、認証トークン、APIキー |
| カウンターの値のように、見られても困らないもの | クレジットカード番号や個人情報 |

アプリに認証機能を付けるなら、パスワード自体は端末に保存しません。
ログインのときにサーバーへ送り、代わりに受け取るトークンという文字列を保存します。
トークンには有効期限を設定でき、漏れた場合もサーバー側で無効にできるので、パスワードより影響を抑えられます。

## 機密情報を保存する

トークンのような機密情報には、OSの安全な保存先を使います。
iOSのキーチェーンやAndroidのキーストアは、この目的のために用意された機能です。
[flutter_secure_storage](https://pub.dev/packages/flutter_secure_storage) で利用できます。

```bash
flutter pub add flutter_secure_storage
```

```dart
import 'package:flutter_secure_storage/flutter_secure_storage.dart';

const storage = FlutterSecureStorage();

Future<void> saveToken(String token) async {
  await storage.write(key: 'token', value: token);
}

Future<String?> loadToken() async {
  return storage.read(key: 'token');
}

Future<void> deleteToken() async {
  await storage.delete(key: 'token');
}
```

ログアウトのときは `deleteToken` で消します。
iOSのキーチェーンの内容は、アプリを削除しても残ることがあります。
再インストールした後に以前のログインが残っていて不審に思ったら、この動作を確認します。
Androidでは、自動バックアップとの組み合わせで読み出しに失敗することがあるので、パッケージのReadmeに書かれた設定を確認します。

この保存先も完全ではありません。
OSの制限を解除した端末では、取り出される可能性が残ります。
だからこそ、端末に置く情報は必要最小限にして、有効期限を設けます。

## その他の注意点

- ログに出力しない：`print` の出力は、リリースビルドでも端末のログに残ることがあります。トークンなどを `print` で確認した場合は、コミットする前に取り除きます。
- アプリ側のチェックを信用しない：アプリとサーバーの間の通信は、自作のプログラムで再現できます。購入の確認や権限の判定は、サーバー側で行います。
- 集める情報を減らす：持っていない情報は漏れません。使わない個人情報は取得しないようにします。

第52章のHTTPSも、通信の途中でトークンを盗まれないための手段です。
